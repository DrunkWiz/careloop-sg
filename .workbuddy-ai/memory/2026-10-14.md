# 2026-10-14

## Fixed: red-flag handover not created when a rung-4 handover already exists same day

**Bug:** In `backend/engine/ladder.py` `run_day()`, the handover creation condition
`if out.rung in ("4", "R") and not decision["handover_id"]` meant a red flag reused
an existing rung-4 handover (since `decision["handover_id"]` was inherited from `prev`).

**Fix (two lines in `ladder.py`):**
1. Line 106: changed condition to `if out.rung == "R" or (out.rung == "4" and not decision["handover_id"])`
   so red flags always create their own handover.
2. Line 236 (`_handover`): changed id from `f"ho-{did}"` to `f"ho-{did}-R" if out.rung == "R" else f"ho-{did}"`
   so the red-flag handover doesn't overwrite the rung-4 one.

**Test added:** `test_rung4_handover_then_red_flag_same_day_gets_two_handovers` in
`backend/engine/tests/test_safety_scenarios.py` — verifies two handovers exist and the
second has kind `red_flag`.

**Test results:** engine 26/26 OK (incl. new test), language 54/54 OK, synth 4/4 OK.
api and reports suites fail on missing `fastapi`/`reportlab` packages (pre-existing, unrelated).
